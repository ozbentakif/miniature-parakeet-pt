# WDS prototype (Wise Digital-Marketing Spending)

A working prototype of WDS, a rule-based tool that checks paid-ad campaigns on Meta, Google and TikTok every hour, pauses or flags the ones losing money, and records every decision with its reason.

**Live app:** https://ozbentakif.github.io/miniature-parakeet-pt/

## What to look at
1. **Dashboard.** It opens on "today" (1 Aug 2026) with WDS just switched on. The two starter rules have already checked every campaign. "Needs your attention" lists the stop-loss approval requests. Approve or decline one. Declining asks for a one-click reason.
2. **Replay July.** Press "Replay July", then "Play". The month runs one day per step as if WDS had been live. Play stops when something needs you: on the sample data, the lead drop-off rule pauses a campaign automatically on 14 Jul. Select the campaign to see the drop in its daily chart, then undo the pause or let it run. The card at the top shows the loss avoided and the profit given up by the pauses so far.
3. **Inbox.** Drop a CSV with the same columns into the inbox. The next sync (4 seconds in the demo) reads it, rejects impossible rows with a reason, and restarts the dashboard on that data. Manual upload is the fallback.

The Rules and Audit log tabs are shown to place the prototype in the full product, but they are not built.

## What it does
- **Dashboard:** spend, leads, cost per lead, qualification rate and ROAS for each campaign and for the portfolio, over the last 7 days, the last 14 days or the whole file. Selecting a campaign shows its daily spend against revenue and its leads against the 7-day average.
- **Starter rules**, with the thresholds from the decision memo:
  - *Lead drop-off (acts automatically):* $300+ spent in the last full day, leads below 20% of the 7-day daily average, clicks at least half of normal.
  - *Quality stop-loss (asks for approval):* ROAS below 100% over the last 14 fully qualified days, with $1,500+ spent.
- **Company limits** are applied before any rule acts. TikTok is read-only, so rules there only alert. Campaigns with under 14 days of history only get a warning. Rules do not act on flagged data (frozen values, missing days, or many campaigns on one platform losing leads at once) until a buyer reviews it.
- **One action per problem.** A rule acts once when its condition starts. It acts again only after the condition has cleared and come back. Open requests close by themselves when the condition clears.
- **Manual actions:** pause or resume a Meta or Google campaign with a one-click reason.
- Every sync, flag, rule action and buyer response is written to an in-memory audit log. A campaign's recent entries appear in its detail panel.

## Assumptions and limits
- **ROAS** = $55 × qualified leads ÷ spend, so 100% is break-even. **Cost per lead** is per submitted lead.
- **No look-ahead.** Qualification arrives 1 to 3 days after a lead is submitted, so on any day only data at least 3 days old counts as fully qualified. ROAS and the stop-loss use those days only. The CSV is fully backfilled, so the app hides the newer qualification data itself.
- **"Today"** is two days after the last date in the file. Platform data runs to the day before; the file has no row for the day in between.
- **Daily steps.** Live WDS syncs hourly. The data is daily, so the replay moves one day per sync.
- **History.** Campaigns with data on the file's first day are treated as older than 14 days. In the live system, imported history would answer this.
- **Loss avoided** is measured on the days a campaign was paused, using the full qualification data.
- **Simulated.** There are no platform APIs and no live AI. Pauses, alerts and approvals are not sent anywhere. Files are read in the browser and never uploaded.
- **Sample data.** The built-in data is synthetic, generated by `scripts/make_sample.py`. It has the same columns as a 30-day extract and the same kinds of patterns: a tracking drop, a slow decline, cheap leads that rarely qualify, a late-starting campaign, small noisy campaigns and two invalid rows.

## Run locally
Requires Node.js 24.

```bash
npm install
npm run dev      # start the app
npm test         # run the unit tests
npm run build    # production build in dist/
```

Python helper scripts (Python 3, standard library only):

```bash
py scripts/make_sample.py               # regenerate public/sample.csv
py scripts/profile_csv.py path/to/file.csv
```

## Project structure
```
src/core/     engine in plain TypeScript, no UI code: CSV validation, metrics, data flags,
              rules and company limits, the simulated clock, the audit log; Vitest tests beside each file
src/ui/       React components: dashboard, attention queue, campaign detail, charts (plain SVG), inbox
scripts/      sample data generator and data profiler (Python)
.github/      CI: lint, test and build on every push; manual deploy to GitHub Pages
```

`src/core/backtest.ts` replays a rule over past data without look-ahead. It is used to check the rules against data, and is not yet shown in the app.

## How it was built
Built with Claude Code (Anthropic) as a coding assistant. I set the scope, the rules, the thresholds and the no-look-ahead model. Before building the screens, I checked the engine's results against the figures in my decision memo.
